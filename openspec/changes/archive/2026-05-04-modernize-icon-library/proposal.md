# Change: Modernize Icon Library

## Why

The icon library was originally designed with a **dual access** model — every SVG was both a tree-shakable React component AND a publicly served static asset under `https://reltio.design/icons/<name>.svg`. The recently shipped illustration library deliberately rejected this dual model in favor of a single React-component access path, on the grounds that:

1. Consumers tend to use the React import in practice; the public URL is rarely exercised.
2. A second access path doubles the API surface that has to stay coherent (URL stability, CDN caching, naming, license attribution, theming).
3. Raw SVGs served from a CDN cannot pick up the host application's CSS variable cascade — they always render with whatever fill is baked in. The platform's icons use `fill="currentColor"`, but this contract becomes increasingly fragile as the icon set grows and as we want richer theming (e.g. multi-color icons in the future).

The icon library should follow the same single-access-path philosophy as the illustration library so the two libraries are consistent. At the same time, every per-icon Storybook story should render under both light and dark themes simultaneously — same matrix pattern that already exists for illustrations — so each story doubles as a Chromatic regression case for both themes without having to toggle the toolbar.

## What Changes

- **REMOVED** Public URL access for raw SVG icons. The `public/icons/` folder is deleted; SVG sources move to `icons/_source/` as a private build artifact, mirroring `illustrations/_source/`. Storybook (and the deployed site) no longer serves `/icons/<name>.svg`.
- **REMOVED** The "Direct URL" / "URL" column in the Storybook `IconLibrary` catalog block. The block now displays only the icon preview and the React import snippet.
- **MODIFIED** `scripts/build-icons.mjs` to read sources from `icons/_source/` instead of `public/icons/`. The script also now emits per-icon Storybook stories with the same 2-row × 1-row matrix used by illustrations: a light-theme row (small/medium/large/colored variants) above a dark-theme row, each row wrapped in an explicit `data-theme="horizon-light"` / `data-theme="horizon-dark"` div with `background: var(--sapBackgroundColor)`.
- **MODIFIED** Generated `icons/Icons.stories.tsx` so every per-icon story shows both themes side-by-side. The matrix layout is shared via `icons/IconStories.module.css`.
- **MODIFIED** `guides/icon-library.story.mdx` to document the React component as the single access path and to remove all references to the public URL pattern. The guide explains the rationale (consistency with illustrations + future-proofing for multi-color icons).
- **MODIFIED** `openspec/specs/icon-library/spec.md` — drop the **Dual Access Patterns** requirement (specifically the "Direct URL" scenario and the bullet stating that SVGs are served via `/icons/<name>.svg`), update **SVG Source Management** to reference `icons/_source/` as the private build-artifact location, and add a new requirement for the per-story theme × size matrix.

## Impact

- **Affected code**:
  - `public/icons/` — deleted; existing SVG files move to `icons/_source/`.
  - `icons/_source/` — new build-artifact folder containing kebab-case `.svg` sources, mirroring `illustrations/_source/`.
  - `scripts/build-icons.mjs` — `ICONS_SOURCE_DIR` constant retargeted to `icons/_source/`; story generator emits the light/dark matrix.
  - `icons/Icons.stories.tsx` — regenerated by the build script.
  - `icons/IconStories.module.css` — extended with `.row` and matrix layout (mirrors `illustrations/IllustrationStories.module.css`).
  - `.storybook/blocks/IconLibrary.tsx` — URL column removed; the block now renders preview + import snippet only.
  - `.storybook/blocks/IconLibrary.module.css` — URL-cell styles dropped.
  - `guides/icon-library.story.mdx` — Direct URL section removed, dual-access references replaced with single-access-path narrative consistent with the illustration guide.
  - `openspec/specs/icon-library/spec.md` — updated as described above.
- **Affected APIs**: Removes the `https://reltio.design/icons/<name>.svg` URL surface. The TypeScript / React import API is unchanged: `import { Search } from "@reltio/design/icons"` continues to work exactly as before.
- **Dependencies**: No new runtime dependencies. No build-tool changes.
- **Distribution**: Icons continue to ship as inline SVG inside generated React components. Tree-shaking behavior is unchanged.
- **Breaking changes**: YES — any consumer that loads icons via the public CDN URL (`https://reltio.design/icons/<name>.svg`, `<img src="…/icons/foo.svg">`, CSS `background-image: url(…)`) will break. Migration is to import the corresponding React component instead. There is no known internal consumer using the URL path, but external consumers must be notified via the changelog.
- **Migration**:
  - Search call sites for `/icons/*.svg` and `reltio.design/icons` references; replace with named imports from `@reltio/design/icons`.
  - For consumers that genuinely need raw SVG (email templates, marketing pages), a follow-up change can introduce a baked-fill variant — same path the illustration library reserved for itself.
