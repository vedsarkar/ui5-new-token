## Context

The platform enforces a single distribution contract: consumer apps install `@reltio/design` and never `@ui5/*` directly ([single-distribution-package decision](https://reltio.design/?path=/docs/guides-ui-architecture--docs)). Components, charts, hooks, and utils already honor this; icon registration is the remaining gap.

Icon registration is the remaining gap in that contract.

**Before this change:**

- **Custom Reltio icons** (`reltio/*`) are generated by `scripts/build-icons.mjs` from `public/icons/` into flat `icons/<kebab>.tsx`. Consumers import `@reltio/design/icons/<kebab-name>` and render `<Icon name="reltio/<kebab-name>" />`. That flat publish path cannot safely coexist with SAP per-icon modules at the same depth.
- **SAP Fiori icons** require consumers to `import "@ui5/webcomponents-icons/dist/<kebab-name>.js"`. `guides/icon-library.story.mdx` documents this `@ui5` path.

**This change ([DESIGN-96](https://reltio.jira.com/browse/DESIGN-96)):** re-export SAP Fiori icons through `@reltio/design`, unify both families on the same per-icon module contract, and publish under namespaced paths — `icons/sap/` and `icons/reltio/` — so kebab-name overlap cannot collide at module resolution time.

## Architecture

Two **source** directories, **two publish namespaces**, **one module shape** for both families.

```
┌─────────────────────────────────────────────────────────────────┐
│ Consumer apps                                                    │
│                                                                  │
│ Reltio custom:                                                   │
│   import "@reltio/design/icons/reltio/data-quality"              │
│   <Icon name="reltio/data-quality" />                            │
│   import { ReltioDataQuality } from "…/reltio/data-quality"      │
│                                                                  │
│ SAP Fiori:                                                       │
│   import "@reltio/design/icons/sap/decline"                      │
│   <Icon name="decline" />                                        │
│   import { Decline } from "@reltio/design/icons/sap/decline"     │
└───────────────────────────────┬─────────────────────────────────┘
                                │
┌───────────────────────────────┴─────────────────────────────────┐
│ dist/icons/sap/decline.js      dist/icons/reltio/data-quality.js │
└───────────────────────────────┬─────────────────────────────────┘
         ┌──────────────────────┴──────────────────────┐
┌────────┴────────┐                          ┌─────────┴─────────┐
│ icons/reltio/   │                          │ icons/sap/        │
│ build-icons.mjs │                          │ build-sap-icons   │
│ public/icons/*  │                          │ @ui5/.../dist/*   │
└─────────────────┘                          └───────────────────┘
```

**Rules:**

- **Reltio published path:** `@reltio/design/icons/reltio/<kebab-name>`; aggregate `@reltio/design/icons/reltio`.
- **SAP published path:** `@reltio/design/icons/sap/<kebab-name>`.
- **Module shape:** registration on evaluate + PascalCase named export from the **same** path.
- **Render `name`:** Reltio → `reltio/<kebab-name>`; SAP → `<kebab-name>` (bare, no `sap/` prefix).
- **Component export names:** SAP → `Decline`; Reltio → `ReltioDataQuality` (`Reltio` + PascalCase kebab).
- **Source layout:** `icons/reltio/` and `icons/sap/` under repo-root `icons/`.
- **Compile:** `tsc` → `dist/icons/reltio/` and `dist/icons/sap/`.

## Goals / Non-Goals

**Goals:**

- Shared icon-module contract for Reltio and SAP icons.
- No `@ui5/*` in consumer apps for standard SAP icons.
- Tree-shaking per icon.
- **Primary:**

  ```tsx
  import "@reltio/design/icons/sap/decline";
  <Icon name="decline" />

  import "@reltio/design/icons/reltio/data-quality";
  <Icon name="reltio/data-quality" />
  ```

- **Optional component (same path):**

  ```tsx
  import { Decline } from "@reltio/design/icons/sap/decline";
  import { ReltioDataQuality } from "@reltio/design/icons/reltio/data-quality";
  ```

- Docs + Storybook; minor changeset.

**Non-Goals:**

- `tnt` / `business-suite` collections in v1.
- Consumer repo migrations (follow-up).
- Full SAP catalog in Storybook (~700 stories).
- SAP aggregate import (`@reltio/design/icons/sap`).
- PascalCase **paths** (`@reltio/design/icons/Decline` or `@reltio/design/icons/ReltioDataQuality`).

## Decisions

### Decision 1 — Symmetric source directories, namespaced publish

SAP → `icons/sap/` → `dist/icons/sap/`. Reltio → `icons/reltio/` → `dist/icons/reltio/`.

### Decision 2 — Shared module shape (both generators)

**Reltio** (`icons/reltio/<kebab>.tsx`):

```tsx
import { unsafeRegisterIcon } from "@ui5/webcomponents-base/dist/asset-registries/Icons.js";
import { Icon, type IconProps } from "@reltio/design/components";

unsafeRegisterIcon("data-quality", {
  collection: "reltio",
  viewBox: "…",
  customTemplateAsString: "…",
});

const ICON_NAME = "reltio/data-quality";

export type ReltioDataQualityProps = Omit<IconProps, "name">;

export function ReltioDataQuality(props: ReltioDataQualityProps) {
  return <Icon name={ICON_NAME} {...props} />;
}
```

**SAP** (`icons/sap/<kebab>.tsx`):

```tsx
import "@ui5/webcomponents-icons/dist/decline.js";
import { Icon, type IconProps } from "@reltio/design/components";

const ICON_NAME = "decline";

export type DeclineProps = Omit<IconProps, "name">;

export function Decline(props: DeclineProps) {
  return <Icon name={ICON_NAME} {...props} />;
}
```

### Decision 3 — Extend `build-icons.mjs`

- Emit `icons/reltio/<kebab-name>.tsx` with registration **and** `Reltio*` PascalCase export.
- Aggregate at `icons/reltio/index.ts` → `@reltio/design/icons/reltio` only.

### Decision 4 — Add `build-sap-icons.mjs`

Enumerate `@ui5/webcomponents-icons/dist/*.js` → `icons/sap/<kebab>.tsx`; `tsc` compiles to `dist/icons/sap/`.

### Decision 5 — No collision policy

Reltio and SAP may share kebab names (e.g. `cart`, `compare`) — they resolve to different import paths. All Reltio product glyphs are kept.

### Decision 6 — v1 SAP scope: default collection only

### Decision 7 — Storybook and docs

- **`icons/icons.story.mdx`** — dual-family import examples under `icons/sap/` and `icons/reltio/`.
- **`icons/icons.stories.tsx`** — `Icons/Reltio Icons Catalog` (per-icon showcase for Reltio glyphs).
- **Icon Library guide** — separate import paths per family, optional PascalCase component examples (`ReltioDataQuality`, `Decline`); SAP icon names from the [UI5 Icons explorer](https://ui5.github.io/webcomponents/icons/).

## Risks / Trade-offs

- **[Risk] ~700 + ~109 generated modules** — repo size, UI5 bump diffs. → Accepted.
- **[Trade-off] Two import prefixes** — slightly more to learn, but eliminates namespace collisions entirely.
- **[Trade-off] Two `Icon name` shapes** (`reltio/…` vs bare). → UI5 registry reality.

## Migration Plan

**Platform:**

1. Shared per-icon module template (`icon-module-codegen.mjs`); generate `icons/reltio/` from SVGs and `icons/sap/` from pinned `@ui5/webcomponents-icons`.
2. Run both generators; commit output under `icons/reltio/` and `icons/sap/`.
3. Docs, Storybook, changeset.

**Consumers:**

- SAP: replace `@ui5/webcomponents-icons` with `@reltio/design/icons/sap/<kebab>`.
- Reltio: import from `@reltio/design/icons/reltio/<kebab>`; optional `Reltio*` component from the same path.
