## 2. Target matcher — pattern compiler

- [ ] 2.1 Create `packages/auth/src/core/proxy/targetMatcher.ts` exporting `compileTargetPatterns(patterns: string[]): (url: URL) => boolean`. The compiler MUST validate every pattern at construction time and throw a `TypeError` whose message names the offending pattern and the violation reason. Validation covers: `https://` scheme required; no port in pattern; no query/fragment in pattern; wildcards (`*`, `**`) only as the leading host label; no merged wildcard like `*foo` (must be followed by a `.`); glob characters (`*`, `**`, `?`, `[`, `]`, `{`, `}`) inside path rejected except a single trailing `*` (which is sugar for "path prefix"); literal `https://`, `http://`, `://` prefixes parsed before validation so the error message is precise. The compiler MUST be deterministic and pure — no async, no I/O.
- [ ] 2.2 Encode the wildcard semantics in the returned matcher: literal host (case-insensitive), `*.<rest>` (exactly one DNS label, no `.` inside), `**.<rest>` (one or more DNS labels at any depth, both must match at least one label and never the apex). Match against `URL.host` (so non-default explicit ports do NOT match port-less patterns) and `URL.pathname` (so dot-segment resolution from the URL parser is respected). Path comparison uses `startsWith` on the parsed `pathname`.
- [ ] 2.3 Author `packages/auth/tests/core/targetMatcher.test.ts` (Vitest, Node mode). Cover every wildcard scenario from `specs/auth/spec.md` § `Proxy target allowlist`: exact host match, `*` matches single label, `*` rejects multi-label, `*` rejects apex, `**` matches single label, `**` matches deep, `**` rejects apex, path prefix matches, path prefix rejects non-matching path, path case-sensitivity, host case-insensitivity, trailing `*` sugar, path traversal (`/api/../admin` → `/admin`) not bypassing, `%2e%2e` percent-encoded traversal not bypassing, OR-combination of multiple entries, query-string preserved during forward but ignored during match, default-port match, explicit-port non-match, and construction-time errors for every invalid-pattern category (`http://`, no-scheme, mid-host wildcard, merged wildcard, port in pattern, glob in path, query in pattern). At least one assertion per category.

## 3. Proxy handler — request rewriting

- [ ] 3.1 Create `packages/auth/src/core/handlers/proxyHandler.ts` exporting a `Handler` (re-using the existing `HandlerContext` shape from `src/core/handlers/types.ts`). The handler reads `request.headers.get("reltio-target-url")`, returns `400` on missing/empty/whitespace, returns `400` on parse failure, returns `400` if `URL.protocol !== "https:"`, returns `403` if the matcher rejects the URL, returns `401` on absent or empty `access_token` cookie (read via the existing `getAccessToken` helper that already short-circuits empty strings to `null`), and otherwise builds and forwards the outgoing `fetch`.
- [ ] 3.2 Implement the request-side header rewriting: strip the inbound `Authorization`, `Cookie`, `reltio-target-url`, `Host`, and `Content-Length` headers; strip RFC 7230 § 6.1 hop-by-hop headers (`Connection`, `Keep-Alive`, `Transfer-Encoding`, `TE`, `Trailer`, `Upgrade`, `Proxy-Authenticate`, `Proxy-Authorization`) plus any header named in the inbound `Connection` header's value (the RFC's extension-hop-by-hop mechanism); attach `Authorization: Bearer <token>` where `<token>` is the `access_token` cookie value; forward every other inbound header verbatim. Extract this rewriting into a private helper `buildOutgoingHeaders(inbound: Headers, accessToken: string): Headers` inside the same module so the unit tests can drive it directly without going through `fetch`.
- [ ] 3.3 Implement the body forwarding (buffered): for methods that may carry a body (everything except `GET` and `HEAD`), read the inbound body once via `await request.arrayBuffer()` and pass the resulting `ArrayBuffer` (or `Uint8Array`) to the outgoing `fetch` as the `body` option. For `GET`/`HEAD`, do not pass `body`. Defensive JSDoc on the handler notes that this is the buffered v1 path and that `add-auth-proxy-streaming` will replace it with stream forwarding.
- [ ] 3.4 Implement the outgoing `fetch` call with the parsed upstream URL (preserving query string, dropping fragment per fetch semantics — fragments are not sent over the wire by any HTTP client anyway). Do NOT pass an `AbortSignal`. Wrap the `fetch` call in a `try`/`catch`; on `catch`, return `new Response(null, { status: 502 })`.
