# Component Customization

This guide explains how to customize the appearance of every component you can render from a Reltio app — both the **UI5 web components** (Button, Input, Dialog, ...) that come from `@ui5/webcomponents-react` and the **Reltio MDM components** (Chat, Markdown, Details, ...) built on top.

Each layer uses a different mechanism, but they share the same theming foundation: SAP Horizon `--sap*` design tokens delivered through `https://reltio.design/variables.css` and the `data-theme` attribute.

> **🎯 Key Principle:** Restyle UI5 components by overriding `--sap*` tokens or using their CSS Parts. Restyle Reltio components by targeting their stable `reltio_*` CSS classes.

## Two layers, one foundation

```
┌──────────────────────────────────────────────────────────────┐
│  Reltio components       → stable .reltio_* CSS classes      │
│  UI5 web components      → --sap* tokens, ::part() selectors │
└──────────────────────────────────────────────────────────────┘
                              ▲
┌─────────────────────────────┴────────────────────────────────┐
│  SAP Horizon tokens (--sap*) on :root and [data-theme]       │
└──────────────────────────────────────────────────────────────┘
```

Token overrides cascade into both layers automatically. Class-based and `::part()` overrides are the right tool when you need to change something that no token covers.

## Theming foundation (shared)

Reltio Design ships SAP Horizon tokens and SAP 72 fonts as static CSS. Load the files in `<head>` and toggle `data-theme` on any ancestor:

```html
<link rel="stylesheet" href="https://reltio.design/variables.css" />
<link rel="stylesheet" href="https://reltio.design/fonts.css" />

<div data-theme="horizon-light">
  <!-- All UI5 and Reltio components here render in light theme -->
</div>

<div data-theme="horizon-dark">
  <!-- And here in dark theme — nested theming is supported -->
</div>
```

Switching the attribute swaps every `--sap*` value in the cascade. UI5 web components see the change through Shadow DOM automatically; Reltio CSS Modules see it through normal cascade.

See the [Design Tokens guide](?path=/docs/design-tokens--docs) for the full token surface.

### Overriding tokens

Override any `--sap*` token at any DOM level — the change cascades into both UI5 and Reltio components beneath it:

```css
/* Restyle every brand-coloured surface inside .promo */
.promo {
  --sapBrandColor: #e91e63;
  --sapButton_Emphasized_Background: #e91e63;
}
```

```css
/* App-wide override (loaded after variables.css) */
:root {
  --sapBrandColor: #e91e63;
}
```

## Customizing UI5 web components

UI5 components run inside Shadow DOM, so regular CSS class selectors do not reach their internals. Two mechanisms are available, in order of preference:

### 1. `--sap*` design tokens (preferred)

Tokens cross the Shadow DOM boundary natively. Scope them to a parent class to limit blast radius:

```css
.toolbar {
  --sapButton_Background: var(--sapButton_Lite_Background);
  --sapButton_BorderColor: transparent;
  --sapButton_TextColor: var(--sapBrandColor);
}
```

```tsx
import { Button } from "@ui5/webcomponents-react/Button";

<div className="toolbar">
  <Button>Filter</Button>
  <Button>Sort</Button>
</div>;
```

Both buttons render with the lite background, transparent border, and brand text — without touching `::part()` and without wrapping anything.

### 2. CSS Parts (`::part()`)

When no token covers what you need, fall back to UI5's documented CSS Parts:

```css
.pill-bar ui5-button::part(button) {
  border-radius: 999px;
  letter-spacing: 0.04em;
}
```

Each UI5 component documents its parts in the [UI5 Web Components docs](https://sap.github.io/ui5-webcomponents/) — look for the **CSS Parts** section on the component page.

### 3. CSS shadow parts inheritance — what does NOT work

Regular descendant selectors do not pierce Shadow DOM:

```css
/* ❌ Does NOT work — `.icon` lives inside the button's Shadow DOM */
ui5-button .icon { color: red; }

/* ✅ Works — token is inherited through Shadow DOM */
ui5-button { --sapButton_Background: red; }

/* ✅ Works — explicit CSS Part */
ui5-button::part(button) { background: red; }
```

### Restyling vs. wrapping

Do **not** create a Reltio wrapper component just to restyle UI5. Tokens and CSS Parts cover almost every visual tweak. Build a Reltio component only when there is real MDM business logic to add (see [components/AGENTS.md](http://github.com/) and the [UI Architecture guide](?path=/docs/guides-ui-architecture--docs)).

## Customizing Reltio components

Reltio components ship as React components with CSS Modules — regular DOM, no Shadow boundary. Target them via stable, prefixed CSS classes.

### How stable classes work

Every rendered element in a Reltio Design component carries two CSS classes:

1. A **stable class** with `reltio_` prefix — consistent across all builds
2. A **hashed class** — used internally by CSS Modules for scoping

```html
<!-- Rendered DOM -->
<div class="reltio_Chat_root Chat_root__L1VzZ">
  ...
</div>
```

The stable class `reltio_Chat_root` is the public selector you target in your CSS. The hashed class `Chat_root__L1VzZ` is an implementation detail — never depend on it.

### Discovering available classes

Every Reltio component's documentation page includes a **CSS Classes** table that lists all available stable selectors. Click any selector to copy it to your clipboard.

### Overriding styles

Target the stable class in your application's CSS:

```css
/* Tweak the chat scroll-to-bottom button */
.reltio_Chat_scrollToBottom {
  background: var(--sapButton_Emphasized_Background);
  color: var(--sapButton_Emphasized_TextColor);
}

/* Customize a markdown heading colour */
.reltio_Markdown_root h2 {
  color: var(--sapBrandColor);
}
```

### Specificity

Component styles use a single hashed class selector. Your override with the stable class has the same specificity. The CSS cascade determines which wins — **the stylesheet loaded last takes precedence**.

In most setups, your application's CSS loads after the component library's CSS, so your overrides win naturally.

If you need guaranteed specificity regardless of load order:

**✅ Do:** Double the selector or use a parent context

```css
.reltio_Chat_root.reltio_Chat_root {
  font-size: 16px;
}

/* or */
.my-app .reltio_Chat_root {
  font-size: 16px;
}
```

**❌ Don't:** Use `!important`

```css
.reltio_Chat_root {
  font-size: 16px !important;
}
```

## Combining all three approaches

Token overrides re-theme everything; UI5 CSS Parts handle web-component tweaks; Reltio stable classes handle our wrapper components. They compose freely:

```css
/* Re-brand everything */
:root {
  --sapBrandColor: #e91e63;
  --sapButton_Emphasized_Background: #e91e63;
}

/* Tweak a UI5 button's shape inside a specific bar */
.pill-bar ui5-button::part(button) {
  border-radius: 999px;
}

/* Adjust a Reltio component */
.reltio_Markdown_root pre {
  border-left: 3px solid var(--sapBrandColor);
}
```
