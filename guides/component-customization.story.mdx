# Component Customization

This guide explains how to customize the appearance of Reltio Design components in your application. It covers the two main customization mechanisms: **stable CSS classes** for targeted overrides and **global CSS custom properties** for system-wide theming.

> **🎯 Key Principle:** Every component exposes stable, prefixed CSS class names that act as public selectors for external styling. Use them to override any CSS property without modifying the component library.

Components reference global tokens for colors internally, so changing a token propagates to every component that uses it. Stable classes let you override any specific property on a specific element when global tokens are not enough.

## Stable CSS Classes

### How It Works

Every rendered element in a Reltio Design component carries two CSS classes:

1. A **stable class** with `reltio_` prefix — consistent across all builds
2. A **hashed class** — used internally by CSS Modules for scoping

```html
<!-- Rendered DOM -->
<button class="reltio_Tabs_tab Tabs_tab__L1VzZ">
  First Tab
</button>
```

The stable class `reltio_Tabs_tab` is the public selector you target in your CSS. The hashed class `Tabs_tab__L1VzZ` is an implementation detail — never depend on it.

### Overriding Styles

Target the stable class in your application's CSS:

```css
/* Change tab text color and font size */
.reltio_Tabs_tab {
  color: #333;
  font-size: 16px;
}

/* Change the active tab indicator color */
.reltio_Tabs_active::after {
  background-color: hotpink;
}
```

### Specificity

Component styles use the hashed class selector (single class specificity). Your override with the stable class has the same specificity. The CSS cascade determines which wins — **the stylesheet loaded last takes precedence**.

In most setups, your application's CSS loads after the component library's CSS, so your overrides win naturally.

If you need guaranteed specificity regardless of load order:

**✅ Do:** Double the selector or use a parent context

```css
.reltio_Tabs_tab.reltio_Tabs_tab {
  font-size: 16px;
}

/* or */
.my-app .reltio_Tabs_tab {
  font-size: 16px;
}
```

**❌ Don't:** Use `!important`

```css
.reltio_Tabs_tab {
  font-size: 16px !important;
}
```

## Global CSS Custom Properties

### Loading the Tokens

Reltio Design mirrors the SAP Horizon design-token system 1:1. Activate the active theme by wrapping your React app in `<ThemeProvider>` from `@reltio/design`:

```jsx
import { ThemeProvider } from "@reltio/design";

<ThemeProvider>
  <App />
</ThemeProvider>;
```

The provider injects the appropriate per-theme stylesheet (`https://reltio.design/themes/horizon-{light,dark}.theme.css`) and registers the SAP 72 `@font-face` rules. After that, every `--sap*` design token is available on `:root` for components and your own CSS.

For non-React consumers (static sites, MDX docs, server-rendered pages without React control over `<head>`), reference the same files via raw CSS:

```js
// npm subpath import
import "@reltio/design/themes/horizon-light.css";
```

```html
<!-- or via CDN -->
<link rel="stylesheet" href="https://reltio.design/themes/horizon-light.theme.css" />
```

### Using Tokens in Your Application

Reference tokens in your own CSS to stay consistent with the design system:

```css
.my-card {
  background: var(--sapBaseColor);
  border: 1px solid var(--sapField_BorderColor);
  border-radius: var(--sapElement_BorderCornerRadius);
  color: var(--sapTextColor);
}

.my-card-title {
  color: var(--sapBrandColor);
}
```

When the active theme switches (light ↔ dark), every `--sap*` token re-resolves to its theme-specific value and your component re-renders automatically.

### Theming model

Themes are mutually exclusive at runtime — only one is loaded into the page at a time, via a `<link rel="stylesheet">` injected by `<ThemeProvider>`. Switch with the `useTheme` hook:

```jsx
import { useTheme } from "@reltio/design";

const ToggleButton = () => {
  const { resolved, setTheme } = useTheme();
  return (
    <button type="button" onClick={() => setTheme(resolved === "horizon-dark" ? "horizon-light" : "horizon-dark")}>
      Switch to {resolved === "horizon-dark" ? "light" : "dark"}
    </button>
  );
};
```

The previous `[data-theme="dark"]` attribute mechanism — and the corresponding ability to nest themes inside a subtree — is no longer supported. One theme per page; this aligns with the SAP UI5 / Fundamental Library Styles convention.

## Combining Both Approaches

For maximum flexibility, combine SAP token references with stable class selectors:

```css
/* Override the brand color for the entire app */
:root {
  --sapBrandColor: #e91e63;
}

/* Then fine-tune a specific component */
.reltio_Tabs_tab {
  font-weight: 700;
  text-transform: uppercase;
}

.reltio_Chip_root {
  border-radius: 4px;
}
```

> **Note on `:root` overrides.** The active per-theme stylesheet declares all `--sap*` values on `:root` too. Your override needs to load **after** the per-theme file so the cascade resolves in your favour — when using `<ThemeProvider>`, place your global CSS import after the React entry point that mounts the provider, or use a more specific selector than `:root`.
