# Component Typing

This guide explains how to type React component props in the Reltio Design Platform. It covers the `HtmlProps` utility for components that wrap a native HTML element, rest-prop forwarding, Storybook integration, and patterns for common scenarios like polymorphic components and wrapping a UI5 web component.

> **🎯 Key Principle:** Declare custom props once. Let `HtmlProps` handle the rest — native HTML attributes, `Omit` conflicts, and Storybook visibility.

## The `HtmlProps` Utility

`HtmlProps` is defined in `utils/types.ts` and exported from `@/utils/types`. It takes two generic arguments:

```tsx
import type { HtmlProps } from "@/utils/types";

type HtmlProps<
  Tag extends keyof React.JSX.IntrinsicElements,
  CustomProps extends Record<string, unknown>,
> = CustomProps & Omit<React.ComponentPropsWithoutRef<Tag>, keyof CustomProps>;
```

**How it works:**
1. `Tag` selects the HTML element (`"div"`, `"button"`, `"details"`, etc.)
2. `CustomProps` is the object type with your component-specific props
3. Native attributes matching any key in `CustomProps` are automatically removed via `Omit`
4. The result is `CustomProps` intersected with the remaining native attributes

This means `className`, `style`, `id`, event handlers, and all other standard attributes are available without declaring them — and custom props with the same name as a native attribute always take precedence.

## Standard Pattern

Every component with a wrapper HTML element follows this structure:

### Type file

```tsx
// ComponentName.types.ts
import type { HtmlProps } from "@/utils/types";

export type ComponentNameProps = HtmlProps<"div", {
  /** Description for Storybook docs */
  customProp?: string;
}>;
```

### Component file

```tsx
// ComponentName.tsx
export const ComponentName = ({
  customProp,
  className,
  ...rest
}: ComponentNameProps) => {
  return (
    <div className={classNames(styles.root, className)} {...rest}>
      {/* content */}
    </div>
  );
};
```

**Key rules:**
- Destructure only the props you use explicitly
- Spread `...rest` onto the wrapper HTML element
- The `Tag` in `HtmlProps` must match the actual wrapper element tag

## Practical Examples

### Simple component (no overlap)

Custom props have unique names — no conflict with native attributes.

```tsx
export type AssistantLoaderProps = HtmlProps<"div", {
  /** Overall size of the loader (e.g. "32px", "2rem"). Defaults to 32px. */
  size?: string;
}>;
```

### Native prop with custom semantics

The `open` attribute exists natively on `<details>`. Declaring it in custom props automatically removes it from the native type, making it visible in Storybook's Props table.

**✅ Do:** Declare the prop in `HtmlProps` custom type

```tsx
export type DetailsProps = HtmlProps<"details", {
  /** @default false */
  open?: boolean;
}>;
```

**❌ Don't:** Manually `Omit` and re-declare

```tsx
export type DetailsProps = {
  open?: boolean;
} & Omit<React.ComponentPropsWithoutRef<"details">, "open">;
```

### Narrowing a native prop type

When a custom prop has a different type from the native attribute (e.g. `size` on `<button>` is `number` natively, but your component uses string literals), `HtmlProps` prevents a silent `never` intersection.

```tsx
export type ChipProps = HtmlProps<"button", {
  variant?: "filled" | "outlined";
  size?: "small" | "medium";
  onClick?: () => void;
  disabled?: boolean;
}>;
```

Without `HtmlProps`, `size?: ("small" | "medium") & number` resolves to `never`. With `HtmlProps`, the native `size` is omitted and only the custom type applies.

### Removing a native prop

When a component does not support a native prop (e.g. `children`), wrap with `Omit` on the outside:

```tsx
export type SkeletonProps = Omit<HtmlProps<"div", {
  rows?: number;
  size?: string;
}>, "children">;
```

### Pure pass-through (no custom props)

Components that add no custom props use `React.ComponentPropsWithoutRef` directly:

```tsx
export type DividerProps = React.ComponentPropsWithoutRef<"hr">;
```

### Polymorphic component

Components that render different elements based on props use a discriminated union with `HtmlProps` for each branch:

```tsx
type BaseButtonProps = {
  variant?: "filled" | "outlined" | "text";
  size?: "small" | "medium" | "large";
  disabled?: boolean;
};

type AsButton = HtmlProps<"button", BaseButtonProps & {
  href?: never;
  type?: "button" | "submit" | "reset";
}>;

type AsAnchor = HtmlProps<"a", BaseButtonProps & {
  href: string;
}>;

export type ButtonProps = AsButton | AsAnchor;
```

Each branch gets its own `HtmlProps` call. `BaseButtonProps` is shared and spread into both — ensuring `size` and `disabled` are properly omitted from the native types of both `<button>` and `<a>`.

### Wrapping a UI5 component

When the wrapper element is **not** a plain HTML tag but a UI5 component (e.g. you build a Reltio business component on top of `Button` from `@ui5/webcomponents-react`), do NOT use `HtmlProps`. Derive the prop type from the UI5 component itself with `ComponentPropsWithoutRef<typeof X>` — this keeps the wrapper aligned with UI5's evolving API and inherits every UI5 prop automatically.

```tsx
// SaveEntityButton.types.ts
import type { ComponentPropsWithoutRef } from "react";
import type { Button } from "@ui5/webcomponents-react/Button";

type Ui5ButtonProps = ComponentPropsWithoutRef<typeof Button>;

export type SaveEntityButtonProps = Omit<Ui5ButtonProps, "design" | "onClick"> & {
  /** ID of the Reltio entity to save */
  entityId: string;
  /** Fired after the entity has been persisted */
  onSaved?: (entityId: string) => void;
};
```

```tsx
// SaveEntityButton.tsx
import { Button } from "@ui5/webcomponents-react/Button";
import { classNames } from "@/utils/classNames";
import styles from "./SaveEntityButton.module.css";
import type { SaveEntityButtonProps } from "./SaveEntityButton.types";

export const SaveEntityButton = ({
  entityId,
  onSaved,
  className,
  ...rest
}: SaveEntityButtonProps) => {
  return (
    <Button
      design="Emphasized"
      className={classNames(styles.root, className)}
      onClick={() => onSaved?.(entityId)}
      {...rest}
    />
  );
};
```

**Rules for UI5 wrappers:**
1. Always derive the base type from the UI5 component (`ComponentPropsWithoutRef<typeof Button>`), never re-list its props by hand.
2. `Omit` UI5 props you fully control internally (e.g. fixed `design`, an overridden `onClick`) so consumers cannot accidentally override them.
3. Spread `...rest` onto the UI5 root and forward `className` through `classNames()` so external customization keeps working.
4. Storybook's auto-docs picks up the wrapper's custom props from `.types.ts` automatically; UI5's own props remain documented on the upstream component page.

## What Not to Declare in Custom Props

Native attributes that keep their standard type and semantics should **not** be re-declared:

**Rule of thumb:** declare a native prop in custom props only when you change its type, restrict its values, or need it visible in Storybook with custom documentation.

## Storybook Props Table

`react-docgen-typescript` determines which props appear in the Storybook Props table based on where they are declared:

- Props declared in `@types/react` (node_modules) are **hidden**
- Props declared in your `.types.ts` file are **shown**

`HtmlProps` ensures this works correctly:
- Custom props are always declared in the component's `.types.ts` file — they appear in the table
- Native-only props come from `@types/react` — they are hidden
- When a custom prop name matches a native attribute, the native one is `Omit`-ed, so only the custom declaration exists — it appears in the table

No additional Storybook configuration is required.
