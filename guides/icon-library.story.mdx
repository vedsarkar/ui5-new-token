# Icon Library Guide

The Reltio Design System provides a comprehensive icon library distributed exclusively as tree-shakable React components. Icons share a single access path — the npm package import — so consumers always benefit from type safety, theme awareness, and bundle optimization.

> **🎯 Key Principle:** Icons ship only as React components. There is no public CDN URL for raw SVG files.

## Why no public URL?

Earlier versions of the library exposed a parallel raw-SVG endpoint at `https://reltio.design/icons/<name>.svg`. That surface was retired for several reasons:

- **Consistency with illustrations.** The illustration library was designed from the start as a single-access library because SAP design tokens only resolve when SVGs are inlined into the host DOM. Aligning icons with the same model removes a confusing "two ways to use" question.
- **Smaller, simpler API surface.** A second access path doubles the maintenance cost (URL stability, CDN caching, naming, attribution, theming) for a use case that no internal product actually needs.
- **Future-proofing.** As icons evolve toward richer semantics (multi-color, theme-aware fills), the React component is the only path that can reliably honor the host's CSS-variable cascade.

If a future use case truly demands non-React consumption (email templates, marketing pages, partner integrations), we can introduce a baked-fill SVG distribution as a follow-up change. For now, every consumer uses the React import.

## Usage

Import the icon component you need:

```tsx
import { SlimArrowDown, AccountCircle } from "@reltio/design/icons";

function MyComponent() {
	return (
		<div>
			<SlimArrowDown size="medium" />
			<AccountCircle color="primary" />
		</div>
	);
}
```

Every named export under `@reltio/design/icons` is a tree-shakable React component. Importing `SlimArrowDown` does NOT pull any other icon's code into the bundle.

For dynamic icon rendering (e.g. picking an icon by name at runtime), import the `iconMap`:

```tsx
import { iconMap, type IconProps } from "@reltio/design/icons";

function DynamicIcon({ name, ...rest }: IconProps & { name: string }) {
	const Icon = iconMap[name];
	return Icon ? <Icon {...rest} /> : null;
}
```

### `className`, `style`, and other HTML attributes

`IconProps` extends the standard `<svg>` HTML props, so all native SVG attributes pass through to the rendered element:

```tsx
<Search className="my-custom-class" />
<Search style={{ marginInline: 8 }} />
<Search data-testid="search-icon" />
```

### `aria-label`

Add an accessible label for meaningful icons:

```tsx
<Close aria-label="Close dialog" />
```

## Theming

Icons that use `color="inherited"` follow the host's `currentColor`. Icons that use a semantic color (`primary`, `success`, etc.) read the corresponding SAP Horizon token, which automatically swaps when an ancestor element carries `data-theme="horizon-dark"`.

```tsx
<div data-theme="horizon-light">
	<CheckCircle color="success" /> {/* renders the light-theme positive color */}
</div>

<div data-theme="horizon-dark">
	<CheckCircle color="success" /> {/* renders the dark-theme positive color */}
</div>
```

The Storybook page for each icon renders the icon under both themes side-by-side so the regression coverage doubles per snapshot.

## Accessibility

Icons support two accessibility modes.

### Decorative icons (default)

When no `aria-label` is provided, icons are hidden from screen readers:

```tsx
<Search />
{/* renders <svg aria-hidden="true"> */}
```

Use decorative icons when:

- The icon accompanies visible text (e.g. button labels)
- The icon is purely visual reinforcement
- The meaning is conveyed by surrounding context

### Meaningful icons

When `aria-label` is provided, icons are announced to screen readers. Add `role="img"` so the SVG is treated as an image:

```tsx
<Search aria-label="Search" role="img" />
```

Use meaningful icons when:

- The icon is the only content of a button
- The icon conveys information not available in surrounding text

## Adding a New Icon

Adding icons is a fully automated build-script flow.

### Step 1: Add the SVG

Place your SVG file in `icons/_source/` using kebab-case naming:

```
icons/_source/my-new-icon.svg
```

SVG requirements:

- 16×16 viewBox preferred (matches the SAP Horizon icon set)
- Single-color shapes — fills are stripped automatically and replaced with `currentColor`
- White (`#fff`) and `#d9d9d9` fills are preserved as-is when present (used by SAP for explicit highlights)

> **⚠️ Note:** `icons/_source/` is a build-artifact folder. Files placed there are NOT served at any public URL — they exist only as input to the build script. The published artifact is the React component generated in `icons/`.

### Step 2: Run the generator

```bash
npm run build-icons
```

This regenerates:

- React components (`icons/<PascalName>.tsx`)
- Barrel export (`icons/index.ts`)
- Unified Storybook stories (`icons/Icons.stories.tsx`)
- Biome formatting across all generated files

### Step 3: Verify in Storybook

```bash
npm run dev
```

Your icon appears in:

- The Icon Library catalog on the Docs page
- An individual story rendering the light/dark matrix

## Best Practices

1. **Use semantic colors appropriately** — `success` for positive actions, `warning` for caution, `error` for destructive actions
2. **Always provide `aria-label` for icon-only buttons** — screen reader users need context
3. **Keep sizes consistent** — use the standard `size` prop rather than custom dimensions
4. **Prefer named imports** — they enable tree-shaking; avoid the `iconMap` for known icons
5. **Follow naming conventions** — kebab-case for source files, PascalCase for components
