# Design Tokens

The Reltio Design Platform ships two SAP-branded themes — **SAP Reltio** (light) and **SAP Reltio Dark** — built as a **lightly customized SAP Horizon theme**. We keep SAP Horizon's full token **surface** — every `--sap*` CSS variable is present on `:root` when `variables.css` is loaded — and only adjust the **values** of selected tokens to match the Reltio brand. Token **names, casing, and structure are never changed**, so the themes stay fully compatible with the UI5 web components. Colors **must** use these tokens — never hardcode hex values.

> **🎯 Key Principle:** Same SAP Horizon token names, Reltio-tuned values. Because the names are identical to upstream, UI5 components consume our customized values automatically — no forks, no parallel theme, no per-component overrides.

> **ℹ️ Naming:** **SAP Reltio** / **SAP Reltio Dark** are the display names of the themes. Following SAP's acquisition of Reltio, these brand the customized Horizon theme. The technical identifiers are still SAP Horizon's — `data-theme="horizon-light"` / `horizon-dark` and `sapSapThemeId` = `sap_horizon` / `sap_horizon_dark`. Official registration of the theme with SAP under a dedicated `themeId` is planned; until then, keep using the Horizon identifiers in code.

The same token surface powers both **Reltio components** (CSS Modules under `components/`) and the underlying **UI5 web components** from `@ui5/webcomponents-react` — UI5 reads `--sap*` variables through Shadow DOM automatically, so there is no separate theme system to manage.

## Usage

Load `variables.css` and `fonts.css`, then set `data-theme` on any ancestor element. There are two equivalent ways to load the CSS — both ship the exact same files.

### Option 1 — CDN (`<link>`)

The simplest setup: link the files straight from `https://reltio.design/`.

```html
<link rel="stylesheet" href="https://reltio.design/variables.css" />
<link rel="stylesheet" href="https://reltio.design/fonts.css" />

<div data-theme="horizon-light">
  <!-- UI5 components and Reltio components both render in light theme -->
</div>
```

> **📌 Need a version-pinned URL?** The `https://reltio.design/` URLs always serve the **latest** published files, which may change at runtime as the platform ships updates. Our static assets are hosted on Vercel, so we can provide a **fixed, version-locked CDN URL** for any release — useful if you want to guard against unexpected runtime changes or roll back to a previous version. Reach out to the UI Center of Excellence at [ui.coe@reltio.com](mailto:ui.coe@reltio.com) to get a pinned URL for the version you need.

### Option 2 — Import from the package

`@reltio/design` ships both stylesheets in its published bundle, so a bundler-based app (Vite, webpack, Next.js, …) can import them as side effects — no separate CDN request:

```ts
import "@reltio/design/variables.css";
import "@reltio/design/fonts.css";
```

> **⚠️ Fonts still load from the CDN.** The package ships `fonts.css`, but **not** the `.woff2` binaries. Every `@font-face` rule inside `fonts.css` points its `src` at `https://reltio.design/fonts/*.woff2`, so the font files are always fetched from the CDN — regardless of which option you choose. `variables.css`, by contrast, is fully self-contained (only `--sap*` declarations, no external references).
>
> **Self-hosting fonts?** To serve the `.woff2` files from your own origin (air-gapped or CSP-locked environments), download the SAP 72 binaries yourself and generate your own `fonts.css` whose `src` URLs point at your host — see the [Typography guide](/?path=/docs/guides-typography--docs). Do not rely on `@reltio/design`'s `fonts.css` for that case.

Either way, switch the active theme by toggling `data-theme="horizon-light"` (**SAP Reltio**) or `data-theme="horizon-dark"` (**SAP Reltio Dark**) on any ancestor. Nested theming is supported — a `[data-theme]` on a child element scopes that theme to its subtree.

**CSS** — reference any variable: `color: var(--sapBrandColor)`, `background: var(--sapErrorBackground)`, etc.

### How UI5 consumes the same tokens

UI5 web components live inside Shadow DOM, but CSS custom properties cross that boundary natively. When you set a `--sap*` token at any DOM level — `:root`, a wrapper class, or under a `[data-theme]` element — every UI5 component beneath it picks up the new value automatically:

```css
/* Re-tint every UI5 button inside .promo */
.promo {
  --sapButton_Background: var(--sapButton_Lite_Background);
  --sapBrandColor: #e91e63;
}
```

```tsx
import { Button } from "@ui5/webcomponents-react/Button";

<div className="promo">
  <Button design="Emphasized">Promoted</Button> {/* uses the overridden tokens */}
</div>;
```

This is the **preferred** way to restyle UI5. Fall back to UI5's documented [CSS Parts (`::part()`)](https://sap.github.io/ui5-webcomponents/) only when no token covers the change you need.
