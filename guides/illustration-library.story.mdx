# Illustration Library Guide

The Reltio Design System ships a curated set of full-color illustrations sourced verbatim from the upstream [`SAP/ui5-webcomponents`](https://github.com/SAP/ui5-webcomponents) project (Apache 2.0). Illustrations are consumed exclusively as React components through `@reltio/design/illustrations`.

> **🎯 Key Principle:** Illustrations have one canonical access path — the React component. Their SVG fills reference SAP `--sapContent_Illustrative_Color*` variables, which only resolve when the SVG is inlined into a DOM that loads `public/variables.css`. The React component does this inlining for you and is the only supported way to render an illustration.

## Usage

Import individual illustrations by name:

```tsx
import { NoData, EmptyList, Welcome } from "@reltio/design/illustrations";

function MyEmptyState() {
	return (
		<div>
			<NoData />
			<EmptyList size="spot" />
		</div>
	);
}
```

Each illustration component inlines the SVG bodies for all three sizes into the React DOM, so the SAP CSS variables resolve through the host page's cascade and theme switching is automatic.

All illustration components accept the following props:

Selects the SAP-native art crop and the physical dimensions.

```tsx
<NoData size="spot" />
<NoData size="dialog" />
<NoData size="scene" />
```

### `title`

Sets the accessible label on the wrapping `<div role="img">`. Each component ships with a sensible default; override when the surrounding context calls for more specific copy.

```tsx
<NoData />                                   {/* uses default "No data" */}
<NoData title="No customers found" />        {/* custom label */}
<NoData title="" />                          {/* fully decorative — aria-hidden */}
```

### `description`

Renders into a screen-reader-only span and is announced after the title. Useful when the illustration carries additional meaning that is not present in surrounding copy.

```tsx
<NoData description="Try clearing your filters or adjusting the date range." />
```

### `className`

Custom CSS classes are merged via the platform's `classNames()` utility:

```tsx
<NoData className="my-custom-spacing" />
```

### `style`

Inline styles are applied to the wrapping `<div>`:

```tsx
<NoData style={{ marginTop: 24 }} />
```

### Rest props

All standard `<div>` HTML attributes pass through to the root element:

```tsx
<NoData data-testid="empty-state" id="dashboard-empty" />
```

## Theming

Illustrations switch between light and dark palettes automatically based on the nearest ancestor with `data-theme="horizon-dark"`. There is no theme prop — theme is detected from the CSS cascade.

```tsx
<div data-theme="horizon-light">
	<NoData />          {/* light palette */}
</div>

<div data-theme="horizon-dark">
	<NoData />          {/* dark palette, same component */}
</div>
```

This works because each illustration's inline SVG references SAP `--sapContent_Illustrative_Color*` variables, and those variables are redefined per theme in `public/variables.css`.

### Custom palette

If you need a brand-specific palette, override the SAP variables in your own scope:

**✅ Do:** Override only within a scoped container

```css
.my-app .accent-illustrations {
	--sapContent_Illustrative_Color1: #e91e63;
	--sapContent_Illustrative_Color3: #ff9800;
}
```

```tsx
<div className="accent-illustrations">
	<NoData />
</div>
```

**❌ Don't:** Modify the SVG fills directly — your changes will be lost the next time the build script syncs from upstream.

## Accessibility

Illustration components support two accessibility modes.

### Decorative + descriptive (default)

When a `title` is set (default or overridden), the wrapping `<div>` carries `role="img"` and `aria-label={title}`. The optional `description` is rendered into a screen-reader-only span and announced after the label. Inner `<svg>` elements are marked `aria-hidden="true"` so assistive technology sees a single landmark.

```tsx
<NoData title="No customers" description="Try clearing the search filter." />
{/* Renders: <div role="img" aria-label="No customers"><svg aria-hidden>...</svg><span sr-only>Try clearing the search filter.</span></div> */}
```

### Fully decorative

Pass an empty `title` to opt out of the ARIA landmark entirely:

```tsx
<NoData title="" />
{/* Renders: <div aria-hidden="true">...</div> */}
```

Use this when the illustration accompanies prominent text and adds no informational value to assistive tech.

## Visual Regression Testing

Every illustration story renders a 2-row × 3-column matrix: the **light row** (Spot, Dialog, Scene) over the **dark row** (Spot, Dialog, Scene). Each row forces its theme through an explicit `data-theme` wrapper, so:

- A single Chromatic snapshot per illustration covers both themes simultaneously
- The output is deterministic regardless of the active Storybook toolbar theme
- A designer reviewing a story sees both themes side-by-side without toggling

This makes every Storybook story a self-contained visual + accessibility regression case. When a SAP token changes (or `SAP_REF` is bumped), Chromatic's diffs surface differences in either theme on the first try.

## Tree-Shaking

Each illustration is a separate module under `illustrations/<Name>.tsx`. Modern bundlers tree-shake unused illustrations: importing only `NoData` does not pull `EmptyList`, `Welcome`, or any other wrapper into your bundle.

For very tight bundle budgets, prefer the per-path import form:

```tsx
import { NoData } from "@reltio/design/illustrations/NoData";
```

## Curation Policy

The library is a **curated subset** of the upstream SAP set, not a full mirror. Some upstream illustrations are visually inconsistent with the current SAP Horizon Figma kit that Reltio products align with — older art crops, deprecated `_v1` variants, stylistic regressions in palette or perspective. Shipping all of them verbatim would dilute brand consistency in consumer UIs, so they are filtered out.

Curation is expressed in `scripts/build-illustrations.mjs` through a single explicit allowlist:

```ts
const ILLUSTRATION_NAMES = [
	"Achievement", "AddDimensions", "NoData", /* ... 32 names total */
];
```

Anything not in this list is simply not built — there is no parallel rejected-list. The list is the only contract.

### Adding an illustration

To add a new illustration to the library:

1. Validate the candidate against the current SAP Horizon Figma kit
2. Get design review approval
3. Add the name to `ILLUSTRATION_NAMES` in `scripts/build-illustrations.mjs`
4. Add a default `title` and `description` entry to `illustrations/manifest.json`
5. Run `npm run build-illustrations`
6. Open a PR with the new wrapper, the manifest entry, and the allowlist change in the same commit

### Removing an illustration

Just delete the name from `ILLUSTRATION_NAMES` and re-run `npm run build-illustrations`. The build script's reconcile pass deletes the corresponding wrapper, source SVGs, and updates the index automatically — no manual cleanup required.

## How to Sync from Upstream

The platform pins a specific upstream `SAP/ui5-webcomponents` release in `scripts/build-illustrations.mjs`:

```js
const SAP_REF = "v2.21.1";
```

To pick up new illustrations or fixes from SAP:

1. Browse [SAP/ui5-webcomponents releases](https://github.com/SAP/ui5-webcomponents/releases) and pick a stable tag
2. Update `SAP_REF` in `scripts/build-illustrations.mjs`
3. Run the build:

	```bash
	npm run build-illustrations
	```

	This downloads SVGs into `illustrations/_source/`, validates the inventory and SAP variable references, and regenerates the React wrappers.

4. Review the diff, run `npm run format` and `npm run lint`, and commit.

> **💡 Tip:** the build script fails loudly if upstream introduces a SAP variable that is not yet in our `public/variables.css`. When this happens, sync `tokens/sap_horizon*.tokens.json` first via `npm run build-tokens`, then re-run `npm run build-illustrations`.

## Default Copy

Default `title` and `description` for every illustration live in `illustrations/manifest.json`. To adjust the wording:

1. Edit the entry for the illustration in `illustrations/manifest.json`.
2. Re-run `npm run build-illustrations`.
3. Review the diff in the affected `illustrations/<Name>.tsx`, run `npm run format`, and commit.

Consumers can always override `title` and `description` per usage via props, so manifest defaults are starting points, not lock-ins.
