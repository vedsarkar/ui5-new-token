# Typography

`@reltio/design` ships **SAP 72** as the default text font and **72 Mono** as the default monospace font. This guide shows how to load them in your application and how to use them when writing your own CSS on top of the design system.

> **🎯 Key Principle:** Once the fonts are loaded and the root `font-family` is set, every Reltio component renders in SAP 72 automatically. Your own elements inherit the same family through standard CSS inheritance — you almost never need to declare `font-family` yourself.

## Quick Start (Recommended — React)

The simplest path is to wrap your application in `<ThemeProvider>`. It activates the active theme **and** registers all SAP 72 `@font-face` rules in one step, with all assets served from the `reltio.design` CDN by default.

```jsx
import { ThemeProvider } from "@reltio/design";

export default function App() {
	return (
		<ThemeProvider>
			<YourApp />
		</ThemeProvider>
	);
}
```

That's it — fonts are loaded, `--sap*` design tokens are on `:root`, and every Reltio component renders in SAP 72. The provider listens to the system `prefers-color-scheme` media query and picks the right theme automatically. You can override with `<ThemeProvider defaultTheme="horizon-light">` (or `"horizon-dark"`) if you want to lock the choice.

The root `font-family` SAP 72 declaration is part of the platform's global CSS — you do not need to add anything to your own global stylesheet for the default text family to apply.

## Alternative — non-React consumers

For static sites, server-rendered pages where you can't control `<head>` from React, or MDX docs that render outside a `ThemeProvider`, use raw `<link>` references to the same CDN files:

```html
<link rel="stylesheet" href="https://reltio.design/themes/horizon-light.theme.css" />
<link rel="stylesheet" href="https://reltio.design/fonts.css" />
```

Or import them through the npm package (works in any bundler that handles CSS-as-asset):

```js
import "@reltio/design/themes/horizon-light.css";
import "@reltio/design/fonts.css";
```

The npm versions contain absolute CDN URLs to the font files internally, so no extra static-asset configuration is needed. The browser still downloads the actual `.woff2` files from `reltio.design`.

> **💡 Self-hosting fonts?** If you need to serve the assets from your own origin (offline, air-gapped, locked-down CSP, or production version pinning), `<ThemeProvider>` accepts URL overrides via the `fontUrls` and `fontBaseUrl` props — see the `ThemeProvider` story in Storybook. For non-React setups, download the `.woff2` files directly from SAP ([Fiori Design Web — Font 72 downloads](https://www.sap.com/design-system/fiori-design-web/resources/downloads#font-72)), copy them next to a hand-written `fonts.css`, and adjust the `url(...)` paths inside to point at your own origin.

## Using the Fonts in Your CSS

### Default text — just inherit

The platform relies on CSS inheritance for `font-family`. When you build your own components or page sections on top of `@reltio/design`, do not redeclare the family — your elements pick up SAP 72 automatically from `:root`.

**✅ Do:** Style other properties, leave `font-family` alone

```css
.title {
	font-size: 14px;
	font-weight: 600;
	color: var(--sapTextColor);
}
```

**❌ Don't:** Re-declare a different family

```css
.title {
	font-family: "Roboto", sans-serif; /* breaks visual consistency */
	font-size: 14px;
}
```

### Form controls — use `font-family: inherit`

Browser user agents reset `font-family` on `<input>`, `<textarea>`, `<select>`, and `<button>` elements. To make them inherit from the page, set it back explicitly:

```css
.input {
	font-family: inherit;
	font-size: 14px;
}
```

This is the only place where declaring `font-family` in your component CSS is expected.

### Monospace and code — use the 72 Mono stack

For code blocks, JSON viewers, log output, or any monospace context, use the canonical stack:

```css
.codeBlock {
	font-family: "72 Mono", ui-monospace, "SF Mono", Menlo, Consolas, monospace;
}
```

The fallbacks ensure graceful degradation if 72 Mono fails to load:

- `ui-monospace` — modern OS monospace.
- `"SF Mono"`, `Menlo`, `Consolas` — platform-specific defaults.
- `monospace` — generic family as last resort.

## How Character Coverage Works

Each weight is registered twice in `fonts.css` with different `unicode-range` values:

<table>
	<thead>
		<tr>
			<th>Subset</th>
			<th>Range</th>
			<th>When the browser fetches it</th>
		</tr>
	</thead>
	<tbody>
		<tr>
			<td>Latin</td>
			<td><code>U+0000–00FF</code> + selected Latin punctuation</td>
			<td>Always — typical Western European UI uses only this</td>
		</tr>
		<tr>
			<td>Full Unicode</td>
			<td><code>U+0100–FFFF</code></td>
			<td>Only when a non-Latin character (Cyrillic, Greek, CJK, Arabic, ...) appears on the page</td>
		</tr>
	</tbody>
</table>

You don't need to do anything — the browser picks the right file per character automatically. This keeps the default page weight low (around 50 KB per loaded weight) while still covering international content correctly when needed.

## Why SAP 72

SAP 72 is the native typeface of SAP Fiori. Reltio Design uses SAP Fiori as its primary visual reference, so adopting 72 keeps Reltio surfaces visually consistent with adjacent SAP UI5 web components and the broader enterprise data ecosystem. Practical benefits:

- **Predictable rendering** across operating systems — no more "the text looks slightly different on macOS vs Windows".
- **Smooth visual blending** when Reltio components are embedded next to SAP UI5 web components.
- **Self-hosted, no third-party CDN** — fonts are served from `reltio.design` (or your own origin) with long cache headers.
