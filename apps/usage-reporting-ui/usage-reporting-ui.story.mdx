# Usage Reporting UI

> **Repository:** `reltio-ondemand/usage-reporting-ui`

Usage Reporting UI is an internal Reltio application that provides visibility into platform consumption metrics across tenants. It exposes dashboards for API usage, consolidated profile counts, storage, entitlements, SLA scorecards, and custom reports — all scoped by customer, environment, and tenant via URL query parameters.

```

src/apps/
  summary/                 → Usage summary dashboard (landing view)
  entitlement/             → Entitlement tracking (API, CP, RSU, base package)
  report/                  → Custom SLA and usage reports
  scorecard/               → SLA scorecard view
  storage/                 → Storage usage view
  api/                     → API call volume and trend analysis
  consolidated-profiles/   → Consolidated profile count tracking
src/components/            → Shared UI (Page shell, Header, FilterDialog, etc.)
src/contexts/              → React Contexts (FeaturesContext — feature flags)
api/                       → Express route handlers (proxy, auth, tenants, statistics, etc.)
server/                    → Express server setup and API router registration
utils/                     → Shared hooks, fetch helpers, BigQuery service, logger
types/                     → Global TypeScript type definitions
config/                    → Runtime configuration
test-utils/                → MSW mocks and render helpers
```

## Server Architecture

The application uses a custom Express server rather than Next.js API routes. Route handlers in `api/` are registered through `server/apiRouter.ts`. Key server-side integrations:

- **Proxy** (`api/proxy/`) — forwards authenticated requests to downstream Reltio services, forwarding the `Authorization` header
- **Statistics Reporting** (`api/statisticsReporting.ts`) — aggregates usage statistics
- **Tenants** (`api/tenants.ts`) — tenant list and resolution
- **BigQuery** (`utils/GBQService.ts`) — parameterized queries for SLA and reporting data
- **Auth** (`api/auth.ts`) — OAuth flow via `node-oauth-provider`
- **Config** (`api/config.ts`, `api/nodeConfig.ts`) — runtime configuration surface exposed to the client
- **Health** (`api/healthcheck.ts`) — liveness probe endpoint

Secrets and service URLs are never hardcoded — they are loaded from `config/default.properties` and fetched from Vault via `utils/fetchVaultConfig.ts`.

## Feature Flags

`FeaturesContext` provides runtime feature flags (e.g. `enableSlaReports`) to all feature modules. Permission checks are enforced at the top-level `App` component before any feature module renders.
