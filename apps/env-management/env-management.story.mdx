# Tenant Management

> **Repository:** `reltio-ondemand/env-management`

Env Management is a tenant-scoped operations console that lets administrators schedule, monitor, and control periodic background tasks running against a Reltio environment. It also surfaces internal queue depths, external event-stream integrations, match analysis results, and lifecycle actions — providing a single UI for day-to-day operational tasks across a tenant.

## Application Structure

```
apps/env-management/src/
├── client/
│   ├── App.js                  # Root component — auth, tenant selection, app shell
│   ├── MainContent.js          # Router — maps URL paths to page components
│   ├── actions/                # Redux action creators

│   ├── components/             # Shared UI components (charts, dialogs, tooltips, empty states)
│   ├── pages/                  # Feature pages (see Routes below)
│   └── services/               # Client-side service helpers (configuration, history, logout)
└── server/
    ├── app.js                  # Express app setup, middleware chain
    ├── middlewares/            # Auth, config service, queue proxy, headers, IRS, request signing
    └── services/
        ├── public/             # Health check, error, status endpoints
        └── secured/            # Proxied API routes: config, queues, external queues, IRS, statistics
```

## Server-Side Architecture

The server is a Node.js/Express BFF (Backend for Frontend) that:

- Authenticates users via OAuth (`auth-middleware`, `node-oauth-provider`); reads secrets from HashiCorp Vault.
- Proxies all secured API calls to the Reltio backend, injecting signed credentials and the correct tenant API path (`setApiPath` middleware).
- Fetches internal queue data via `getQueues` (AWS SDK) and Google Cloud credentials.
- Exposes external queue CRUD routes, wrapping provider-specific SDKs behind a unified interface.
- Serves the React SPA via EJS templates with runtime `appSettings` injected into the page.

## Configuration

Runtime configuration is loaded from `/config/default.properties` (and environment-specific overrides). Local development requires a `local.properties` file with `clientSecret`. The active environment is selected via `NODE_CONFIG_ENV`. Google Cloud credentials for queue access are provided through `GOOGLE_APPLICATION_CREDENTIALS`.
