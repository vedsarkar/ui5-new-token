# User Management UI

> **Repository:** `reltio-ondemand/user-management-ui`

User Management UI is a Reltio administration console that enables tenant administrators to manage users, roles, groups, and multi-factor authentication settings across Reltio environments. It is a full-stack application combining a React single-page app with a Node.js/Express BFF (backend-for-frontend) that handles OAuth authentication, tenant resolution, and proxying to Reltio APIs.

## Application Structure

The repository follows a split client/server layout under `src/`:

```
src/
├── server/              # Express BFF
│   ├── app/             # Express app factory, CSP, routing
│   ├── authProxy/       # Proxies authenticated requests to Reltio APIs
│   ├── configService/   # Fetches runtime config from the Reltio Config Service
│   ├── permissions/     # OAuth token introspection and permission checks
│   ├── tenants/         # Tenant list resolution and middleware
│   ├── version/         # Version endpoint
│   ├── reportViolation/ # CSP violation reporting endpoint
│   └── winston/         # Logging setup (Winston + LogDNA)
└── src/                 # React SPA
    ├── actions/         # Redux action creators (auth, UI)
    ├── api/             # Web Workers for async API calls (users, roles, groups, tenants)
    ├── components/      # Reusable UI components
    ├── pages/           # Route-level page components
    ├── reducers/        # Redux reducers
    └── utils/           # Shared utilities
```

## Server (BFF) Responsibilities

The Express server acts as a secure intermediary between the browser and Reltio backend services:

- **Authentication** — OAuth 2.0 login flow via `auth-middleware`; session cookies; SSO redirect handling with automatic `tenant` and `env` parameter injection
- **Auth proxy** — forwards authenticated API requests from the SPA to Reltio APIs, attaching OAuth tokens and cleaning sensitive headers
- **Tenant resolution** — resolves the list of accessible tenants for the authenticated user
- **Config service** — fetches runtime configuration from the Reltio Config Service and exposes it to the SPA
- **Security** — Content Security Policy via Helmet; CSP violation reporting endpoint
- **Logging** — structured Winston logging with optional LogDNA streaming

## Development

```bash
# Install dependencies
npm install

# Start in development mode (webpack-dev-server + Express)
npm start

# Production build (lint + webpack + git-info)
npm run build

# Run tests with coverage
npm run test

# Lint (TypeScript check + ESLint)
npm run lint
```

The development server runs the React SPA on webpack-dev-server and the Express BFF concurrently. The `clientSecret` value in the `development` script must be set to a valid secret before starting (consult the team for the correct value).

## Deployment

The application is containerised using Docker and deployed to Kubernetes via Helm charts located in `devops/helm/user-management-ui/`. The Helm chart configures a `Deployment`, `Service`, `HorizontalPodAutoscaler`, `PodDisruptionBudget`, and an Istio `VirtualService`.

```bash
# Build and run in a container
npm run build
docker image build . -f devops/Dockerfile -t user-management-ui
docker run -e NODE_CONFIG='{"clientSecret":"..."}' user-management-ui npm run production-container
```
