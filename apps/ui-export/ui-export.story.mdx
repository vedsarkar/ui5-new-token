# Export UI

> **Repository:** `reltio-ondemand/ui-export`

UI Export is a standalone Reltio application that lets users create, monitor, and download bulk data export jobs for entities, relationships, graph exports, and segments. It exposes a multi-step wizard for configuring export tasks and a task management view for tracking pending and completed jobs.

## Key Workflows

### Creating an Export Job

The new-task wizard (`NewTask.js`) walks the user through three steps:

1. **Selection** — choose entity types, relationship types, and individual attributes to include. Supports entities, relations, graph exports, and segment-based exports.
2. **Filters** — apply search filters to scope the export to a subset of records.
3. **Job Details** — name the job and select the output format.

### Task Management

The landing page (`Export.js`) shows two tabs — **Pending** and **Completed** — backed by the server-side `/tasks` and `/tasksHistory` endpoints. Completed jobs support infinite scroll with paginated fetching. Users can download output files directly from the **Download** page (`downloadPage/`), which resolves signed or encrypted URLs via the Node proxy before streaming files to the browser.

### Server-Side Proxy

The Express server acts as a secure proxy between the React frontend and the Reltio API:

- Authentication is handled by `auth-middleware` (OAuth 2.0 with Vault-sourced secrets).
- API calls for configuration, tasks, entities, segments, and graph counts are forwarded through dedicated GET/POST routes.
- File downloads are streamed via `downloadFile.js` to avoid buffering large exports in memory.
- Config is injected at startup into `window.REACT_APP_CONFIG` via a generated `config.js` static file.

## Local Development

Start both servers in parallel (React dev server on port 3000, Node proxy on port 8080):

```bash
npm install
npm run start-dev          # Terminal 1 — React dev server
npm run start-dev-server   # Terminal 2 — Node API proxy
```

Open the app at `http://localhost:3000/export`.

Required before running: set `clientSecret` in `config/default.properties` and ensure Bitbucket access to all private library dependencies (see `README.md`).
