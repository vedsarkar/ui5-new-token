# Ontology Builder

> **Repository:** `reltio-ondemand/move-to-reltio-ui`
> **Backend repository:** `reltio-ondemand/move-to-reltio`

**Ontology Builder** (internally known as **Move to Reltio**) is the customer-facing UI for Reltio's AI-powered legacy MDM migration tool. It helps prospects and customers turn an existing legacy data model — Informatica XML, JSON, CSV, or a manually entered schema — into a Reltio L3 configuration with minimal manual effort. The app classifies the uploaded ontology, suggests a matching **Reltio Velocity Pack**, and produces an editable AI-generated entity/attribute mapping with confidence scores. The end deliverable is a Reltio L3 JSON configuration plus a human-readable PDF summary.

The frontend is a **Next.js 16 App Router** application that talks to a separate **Java backend** (`BACKEND_URL`, default `http://localhost:8080`) via a Next.js API route proxy. Session state is held in HTTP-only cookies (`__Host-sessionId`, `__Host-sessionToken`).

## User Journey

1. **Welcome** — Pick "Upload schema" or "Explore Velocity Packs"
2. **Upload schema** — Submit an Informatica XML, JSON, CSV, or manually entered schema
3. **Classify** — Backend runs AI classification and suggests one or more Reltio Velocity Packs with confidence scores and reasoning
4. **Review mapping** — Edit AI-generated entity, attribute, relationship, and lookup-type mappings (`MappingStatus`, confidence chips, source chips)
5. **Generate** — Produce a Reltio L3 JSON configuration and PDF summary
6. **Download** — Download the L3 JSON, PDF, mapping details, and the original input

## Key Patterns

**App Router with a single route group** — All current screens live under `(v2)/` so they share the MUI 7 theme provider (`(v2)/layout.tsx`) without nesting URL segments. The root `/` page server-redirects to `/explore`.

**Backend proxy in a catch-all API route** — `src/app/api/[...path]/route.ts` forwards every browser request to the Java backend, rewriting `sessions/current/...` to `sessions/<sessionId>/...` using the session cookie. Pre-signed S3 download URLs returned by the backend are auto-followed and streamed to the client.

**Public vs. authenticated routes** — `src/proxy.ts` (Next.js middleware) gates routes by version: in v2 the public set is `/`, `/welcome`, `/upload`, `/explore`, `/session-expired`; everything else requires the `__Host-sessionId` cookie.

**Session ID alias** — The client-side `getSessionId()` always returns the string `"current"`; the server-side proxy substitutes the real session ID from the cookie before forwarding to the backend. This keeps the session ID out of client-side JavaScript.

**Frame embedding for reltio.com** — `next.config.ts` sets `Content-Security-Policy: frame-ancestors 'self' *.reltio.com`, allowing the tool to be embedded under the `reltio.com` marketing surface.

## Relation to the platform

Use this directory for cross-app analysis of the legacy-MDM → Reltio migration UX, Velocity Pack visualization, and future SAP Fiori migration planning. Ontology Builder currently consumes **MUI 7**, not `@reltio/design`, so it is a strong candidate for the upcoming UI5 / SAP Horizon migration. Application changes belong in the **move-to-reltio-ui** Bitbucket repository; only platform-owned files (this story, future `CLAUDE.md` / migration notes) live here. To read the application source locally, clone `move-to-reltio-ui` into a VSCode multi-root workspace alongside `reltio-design`.
